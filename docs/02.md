## JobHunt Lite store実装で勘違いしやすい重要ポイントまとめ

### 目的

Reactの登録フォームからLaravel APIへPOSTし、企業情報をDBに保存する。  
保存後は企業一覧を再取得し、画面上の一覧が増えることを確認する。

この章では、以下の流れを理解する。

```text
Reactフォーム入力
↓
form stateで管理
↓
fetchでPOST
↓
Laravel StoreCompanyRequestでバリデーション
↓
Company::create()でDB保存
↓
201 Createdを返す
↓
React側で一覧を再取得
```

---

## 1. `await(...)` ではAPI通信にならない

### 勘違い

```ts
(await `${API_BASE_URL}/companies`, {});
```

### 何が問題か

`await` は「非同期処理の完了を待つ」ための構文であり、API通信そのものを行うものではない。

つまり、URL文字列に `await` を付けても、Laravel APIへリクエストは送信されない。

### 正解

```ts
await fetch(`${API_BASE_URL}/companies`, {});
```

### ポイント

API通信を行うには `fetch()` が必要。  
`await` は `fetch()` の完了を待つために使う。

```ts
const response = await fetch(`${API_BASE_URL}/companies`);
```

---

## 2. `fetch()` の第2引数にはリクエスト設定を書く

### 基本形

```ts
await fetch(`${API_BASE_URL}/companies`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Accept: "application/json",
  },
  body: JSON.stringify(form),
});
```

### 各項目の意味

```ts
method: "POST";
```

Laravel APIへ「登録したい」というリクエストを送る。

```ts
headers: {
  "Content-Type": "application/json",
  Accept: "application/json",
}
```

ReactからLaravelへJSONを送ること、LaravelからJSONで返してほしいことを伝える。

```ts
body: JSON.stringify(form);
```

Reactのオブジェクトである `form` をJSON文字列に変換して送信する。

### 重要

`fetch()` の第2引数に `{}` だけを書くと、POSTメソッド・headers・bodyが指定されていないため、登録APIとしては不十分。

```ts
await fetch(`${API_BASE_URL}/companies`, {});
```

これはAPI通信自体は発生するが、GET扱いになるため、登録処理にはならない。

## 3. `JSON.stringify(form)` が必要な理由

### React側のform

```ts

  name: "",
  media: "",
  priority: "3.0",
  status: "応募済み",
```

これはJavaScriptのオブジェクト。

### APIへ送るとき

```ts

```

API通信では、そのままJavaScriptオブジェクトを送るのではなく、JSON文字列に変換して送る。

### 変換イメージ

```ts

  memo: "React経験が活かせそう"
}
```

これを以下のようなJSON文字列として送る。

```json
{
  "name": "株式会社サンプル",
  "media": "Green",
  "priority": "3.0",
  "status": "応募済み",
  "applied_date": "2026-05-26",
```

## 4. `Content-Type` と `Accept` の違い

### Content-Type

```ts
"Content-Type": "application/json"
```

ReactからLaravelへ送るデータ形式を伝える。

意味：

```text
こちらから送るデータはJSONです。
```

### Accept

```ts
Accept: "application/json";
```

Laravelから返してほしいデータ形式を伝える。

意味：

```text
レスポンスはJSONで返してください。
```

### 教材化ポイント

初学者は `Content-Type` と `Accept` を混同しやすい。

```text
Content-Type：送るデータの形式
Accept：受け取りたいデータの形式
```

## 5. 登録フォーム用の型はsnake_caseでOK

### 取得用の型

```ts
// Laravel APIから取得する企業情報の型。
// React側ではcamelCaseで統一する。
// Laravel側のsnake_caseはCompanyResourceでcamelCaseへ変換する。
export type Company = {
  id: number;
  name: string;
  media: string | null;
  priority: string | null;
  status: string;
  appliedDate: string | null;
  interviewDate: string | null;
  jobUrl: string | null;
  interviewUrl: string | null;
  memo: string | null;
  nextAction: string | null;
  documentResult: string | null;
  firstInterviewResult: string | null;
  secondInterviewResult: string | null;
  finalResult: string | null;
  rejectionStage: string | null;
  createdAt: string;
  updatedAt: string;
};
```

### 登録フォーム用の型

```ts
// 企業登録フォームの入力値を表す型。
// Laravel APIへ送る値なので、DBカラムに合わせてsnake_caseで管理する。
export type CompanyForm = {
  name: string;
  media: string;
  priority: string;
  status: string;
  applied_date: string;
  job_url: string;
  memo: string;
};
```

### 理由

`Company` はLaravel APIから取得して、React画面で表示するための型。  
そのため、React側で扱いやすいcamelCaseにしている。

一方、`CompanyForm` はLaravel APIへPOSTするための送信用データ。  
Laravel側の `StoreCompanyRequest` やDBカラム名がsnake_caseなので、送信用の型もsnake_caseにしている。

### 結論

```text
取得後に画面で使う型：camelCase
Laravelへ送るフォーム型：snake_case
```

役割が違うため、命名規則が違っていても問題ない。

---

## 6. CompanyResourceの役割

### CompanyResourceとは

Laravel APIのレスポンス形式を整えるためのクラス。

DBやModelではsnake_caseのカラム名を使い、Reactへ返すときはcamelCaseへ変換する。

### 例

```php
'appliedDate' => $this->applied_date,
'jobUrl' => $this->job_url,
'createdAt' => $this->created_at,
'updatedAt' => $this->updated_at,
```

### なぜ必要か

Laravel側ではDBカラム名に合わせてsnake_caseを使う。  
React側ではJavaScript/TypeScriptの慣習に合わせてcamelCaseを使う。

CompanyResourceを挟むことで、Laravel内部のDB構造をそのままReactへ漏らさず、フロントエンドが扱いやすい形に変換できる。

### 教材化ポイント

```text
DB・Laravel内部：snake_case
APIレスポンス：CompanyResourceでcamelCaseへ変換
React表示用：camelCase
React送信用：APIが受け取る形に合わせてsnake_case
```

### 注意

登録直後の `store` で `response()->json($company, 201)` を返す場合、レスポンスはsnake_caseのまま返る。

```php
return response()->json($company, 201);
```

そのため、React側で登録直後のレスポンスをそのまま `Company` 型として扱うと、camelCaseとsnake_caseのズレが起きる可能性がある。

ただし、登録後に `fetchCompanies()` で一覧を再取得する設計なら、一覧取得API側でCompanyResourceを通してcamelCaseに変換できるため、表示は安定する。

## 7. storeメソッドの役割

### 実装

```php
public function store(StoreCompanyRequest $request)
{
    $validated = $request->validated();

    $company = Company::create($validated);

    return response()->json($company, 201);
}
```

### 処理の流れ

```text
StoreCompanyRequestで入力チェック
↓
validated()で検証済みデータだけ取得
↓
Company::create()でDB保存
↓
201 Createdで登録結果を返す
```

### 重要

`$request->validated()` を使うことで、バリデーション済みの安全なデータだけを保存対象にできる。

## 8. Controllerに直接バリデーションを書かない理由

### 直接書く例

```php
$validated = $request->validate([
    'name' => ['required', 'string', 'max:255'],
    'media' => ['nullable', 'string', 'max:255'],
    'priority' => ['nullable', 'string', 'max:255'],
    'status' => ['nullable', 'string', 'max:255'],
    'applied_date' => ['nullable', 'date'],
    'job_url' => ['nullable', 'url', 'max:2048'],
    'memo' => ['nullable', 'string'],
]);
```

### 今回の方針

```php
$validated = $request->validated();
```

### 理由

Controllerにバリデーションを書くと、Controllerの責務が増える。

```text
Controller：処理の流れを管理する
FormRequest：入力値を検証する
Model：DB保存を担当する
Resource：APIレスポンスを整える
```

責務を分けることで、コードが読みやすくなる。

## 9. StoreCompanyRequest

### 実装例

```php
<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

/**
 * 企業登録時の入力値を検証するRequestクラス。
 */
class StoreCompanyRequest extends FormRequest
{
    /**
     * このリクエストを許可する。
     */
    public function authorize(): bool
    {
        return true;
    }

    /**
     * 企業登録時のバリデーションルールを返す。
     *
     * @return array<string, mixed>
     */
    public function rules(): array
    {
        return [
            'name' => ['required', 'string', 'max:255'],
            'media' => ['nullable', 'string', 'max:255'],
            'priority' => ['nullable', 'string', 'max:255'],
            'status' => ['required', 'string', 'max:255'],
            'applied_date' => ['nullable', 'date'],
            'job_url' => ['nullable', 'url', 'max:2048'],
            'memo' => ['nullable', 'string'],
        ];
    }
}
```

### `authorize()` の意味

```php
public function authorize(): bool
{
    return true;
}
```

このリクエストを許可するかどうかを返す。  
今回は認証・権限チェックをまだ扱わないため、`true` にしている。

### `rules()` の意味

送られてきた入力値に対して、どのような検証を行うかを定義する。

## 12. getToday関数

### 実装

```tsx
// 今日の日付を yyyy-MM-dd 形式で取得する関数。
// input type="date" の初期値に使う。
function getToday() {
  return new Date().toISOString().slice(0, 10);
}
```

### 目的

応募日の初期値として今日の日付を入れる。

### 理由

`input type="date"` は `yyyy-MM-dd` 形式の文字列を扱うため。

### 注意

`toISOString()` はUTC基準。  
そのため、日本時間の深夜付近では日付がズレる可能性がある。

ただし、Udemy序盤ではまずシンプルに理解するため、この実装で進めてもよい。  
実務寄りの改善章で、ローカル時間基準の関数へ変更する流れにできる。

## 16. handleSubmit

### 実装

```tsx
// 登録フォーム送信時に実行する関数。
// Reactのform stateをLaravel APIへPOSTする。
async function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
  e.preventDefault();

  await fetch(`${API_BASE_URL}/companies`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Accept: "application/json",
    },
    body: JSON.stringify(form),
  });

  await fetchCompanies();

  setForm({
    name: "",
    media: "",
    priority: "3.0",
    status: "応募済み",
    applied_date: getToday(),
    job_url: "",
    memo: "",
  });
}
```

### 目的

フォーム送信時にLaravel APIへ企業情報を登録する。

### `e.preventDefault()` の意味

HTMLのformは、submit時に画面を再読み込みする動きがある。

Reactでは画面遷移や再読み込みをさせず、JavaScriptで送信処理を行いたい。  
そのため、`e.preventDefault()` でデフォルトの送信動作を止める。

### `await fetch(...)` の意味

Laravel APIへのPOSTが完了するまで待つ。

### `await fetchCompanies()` の意味

登録後に企業一覧を再取得する。  
これにより、登録した企業が一覧に表示される。

### `setForm(...)` の意味

登録後にフォームを初期状態へ戻す。

## 18. responseの確認を入れる場合

### 実装例

```tsx
async function handleSubmit(e: React.FormEvent<HTMLFormElement>) {
  e.preventDefault();

  const response = await fetch(`${API_BASE_URL}/companies`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Accept: "application/json",
    },
    body: JSON.stringify(form),
  });

  if (!response.ok) {
    alert("登録に失敗しました");
    return;
  }

  await fetchCompanies();

  setForm({
    name: "",
    media: "",
    priority: "3.0",
    status: "応募済み",
    applied_date: getToday(),
    job_url: "",
    memo: "",
  });
}
```

### 理由

API登録に失敗しているのに一覧再取得やフォームリセットを行うと、ユーザーにとって分かりにくい。

`response.ok` を確認することで、成功時だけ次の処理へ進める。

### 教材の序盤方針

最初はシンプルにPOSTだけ確認してもよい。  
少し進んだら `response.ok` を使ってエラー処理を追加する流れが自然。

## 19. fetchCompanies

### 実装

```tsx
// Laravel APIから企業一覧を取得する関数。
async function fetchCompanies() {
  const response = await fetch(`${API_BASE_URL}/companies`);
  const json = await response.json();
  setCompanies(json);
}
```

### 目的

Laravel APIから企業一覧を取得し、Reactの `companies` stateに保存する。

### 注意

一覧取得APIがCompanyResourceを使ってcamelCaseで返している場合、React側の `Company` 型と一致する。

## 20. useEffect

### 実装

```tsx
useEffect(() => {
  fetchCompanies();
}, []);
```

### 目的

画面初回表示時に企業一覧を取得する。

### `[]` の意味

依存配列が空なので、画面が最初に表示されたタイミングで一度だけ実行される。

## 21. API_BASE_URL

### 実装

```tsx
const API_BASE_URL = "http://127.0.0.1:8001/api";
```

### 注意

Laravelを起動しているポートと一致している必要がある。

例えばLaravelを以下で起動している場合：

```bash
php artisan serve --host=127.0.0.1 --port=8001
```

React側は以下にする。

```tsx
const API_BASE_URL = "http://127.0.0.1:8001/api";
```

### よくあるミス

Laravelを8001で起動しているのに、React側が8000を見ている。

```tsx
const API_BASE_URL = "http://127.0.0.1:8000/api";
```

この場合、別のLaravelアプリや古いサーバーにアクセスしてしまう可能性がある。

## 22. HTMLが返る場合はLaravel APIに当たっていない可能性がある

### 状況

curlやReactからAPIを叩いたとき、JSONではなくLaravelのHTMLエラーページが返る。

### 原因候補

```text
別プロジェクトのLaravelサーバーに当たっている
古いphp artisan serveが残っている
ポート番号が違う
routes/api.phpにルートがない
URLが間違っている
```

### 確認手順

```bash
pwd
```

今いる場所がbackendディレクトリか確認する。

```bash
php artisan route:list --path=api
```

APIルートが存在するか確認する。

```bash
php artisan serve --host=127.0.0.1 --port=8001
```

現在編集しているLaravelを明示的に起動する。

```bash
curl http://127.0.0.1:8001/api/hello
```

今編集しているLaravelにアクセスできているか確認する。

### 教材化ポイント

API確認でHTMLが返る場合、ReactやControllerの実装ミスとは限らない。  
まず、正しいLaravelサーバーに当たっているか確認する。

```tsx
// input type="date" の初期値に使う。

  return new Date().toISOString().slice(0, 10);
}

  const [companies, setCompanies] = useState<Company[]>([]);

  // 企業登録フォームの入力値を管理するstate。
  // Laravel APIへ送信するため、CompanyFormはsnake_caseで管理する。
  const [form, setForm] = useState<CompanyForm>({
    name: "",
    media: "",
    priority: "3.0",
    status: "応募済み",
    applied_date: getToday(),
    job_url: "",
    memo: "",
  });

  // Laravel APIから企業一覧を取得する関数。
  async function fetchCompanies() {
    const response = await fetch(`${API_BASE_URL}/companies`);
    const json = await response.json();

  // Reactのform stateをLaravel APIへPOSTする。
  async function handleSubmit(e: React.FormEvent<HTMLFormElement>) {

      priority: "3.0",
      status: "応募済み",

    fetchCompanies();
```

## 25. この章の最重要まとめ

```text
awaitだけではAPI通信にならない。
API通信にはfetch()が必要。

fetchの第2引数にはmethod、headers、bodyを書く。

ReactのformはJavaScriptオブジェクトなので、APIへ送るときはJSON.stringify(form)する。

CompanyFormはLaravel APIへ送る型なのでsnake_caseでOK。

CompanyはLaravel APIから取得してReact画面で使う型なのでcamelCaseで扱う。

Laravel側ではStoreCompanyRequestでバリデーションする。

Company::create()を使うにはCompany.phpのfillableが必要。

求人URLはjob_urlとして送信し、取得後はCompanyResourceでjobUrlへ変換する。

登録後はfetchCompanies()で一覧を再取得する。

登録成功後はsetFormでフォームを初期化する。
```

## 26. Udemyで強調する詰まりポイント

```text
1. awaitだけ書いても通信されない
2. fetch()の第2引数が空だとPOSTにならない
3. bodyにはJSON.stringify(form)が必要
4. headersのContent-TypeとAcceptの意味が違う
5. CompanyとCompanyFormは役割が違う
6. camelCaseとsnake_caseの使い分けで混乱しやすい
7. CompanyResourceはAPIレスポンス整形用
8. StoreCompanyRequestは入力検証用
9. fillableがないとcreateできない
10. 登録後に一覧を再取得しないと画面が増えない
11. formにonSubmitを付け忘れるとhandleSubmitが動かない
12. button type="submit" と form onSubmit の関係を理解する
13. 求人URLは登録・保存・表示の全箇所に追加が必要
```
