4 JSXのポイント

目的：
詳細ボタンを押した企業の現在データを、モーダル内の input / select / textarea に表示する。
この時点では、PUT更新はまだ行わない。

内容：
isModalOpen と selectedCompany があるときだけモーダルを表示する。
各入力欄の value には editForm の値を紐づける。
入力変更時は setEditForm を使って editForm の一部だけを更新する。
選考結果は select で表示し、「未対応・通過・不通過・保留・辞退」から選択できるようにする。

理由：
selectedCompany は「どの企業を開いているか」を管理するためのstate。
editForm は「モーダル内の入力欄に表示する値」を管理するためのstate。
そのため、JSXでは selectedCompany を直接編集せず、editForm を input / select / textarea の value に使う。

確認：
詳細ボタンを押すとモーダルが開く。
企業名、媒体、志望度、状況、応募日、面談日、求人URL、面談URL、次アクション、選考結果、落選段階、メモが表示される。
各入力欄の値を変更できる。
ただし、この時点では保存してもDB更新は行わない。

重要ポイント：
モーダルの表示条件は isModalOpen && selectedCompany にする。

例：
{isModalOpen && selectedCompany && (

  <div>モーダル内容</div>
)}

理由：
isModalOpen が false のときはモーダルを表示しない。
selectedCompany が null のときは、表示対象の企業がないためモーダルを表示しない。

---

ポイント1：モーダルの外枠

モーダルは画面全体に重ねて表示する。
背景を半透明にし、中央に白いカードを表示する。

実装例：

<div className="fixed inset-0 z-50 flex items-center justify-center bg-black/40 px-4">
  <div className="max-h-[90vh] w-full max-w-4xl overflow-y-auto rounded-2xl bg-white shadow-xl">
    モーダル本体
  </div>
</div>

ポイント：
fixed inset-0 で画面全体に重ねる。
z-50 で他の要素より前面に出す。
bg-black/40 で背景を暗くする。
max-h-[90vh] overflow-y-auto で、内容が多い場合にモーダル内スクロールできるようにする。

---

ポイント2：閉じるボタン

閉じるボタンでは handleCloseModal を呼ぶ。

実装例：
<button
type="button"
onClick={handleCloseModal}

> 閉じる
> </button>

理由：
handleCloseModal では isModalOpen を false にし、selectedCompany を null に戻す。
これにより、モーダルを閉じて選択中の企業情報もリセットできる。

---

ポイント3：input の value には editForm を使う

企業名を表示・編集する場合：

<input
value={editForm.name}
onChange={(e) =>
setEditForm({ ...editForm, name: e.target.value })
}
/>

理由：
selectedCompany は取得した企業データそのもの。
editForm はモーダル内フォーム用の入力値。
input / select / textarea の value には editForm を使う。

---

ポイント4：setEditForm では既存値を残しながら一部だけ更新する

実装例：
setEditForm({ ...editForm, name: e.target.value })

意味：
現在の editForm をコピーし、name だけ新しい値に上書きする。

注意：
以下のように書くと、name 以外の項目が消えるためNG。

setEditForm({ name: e.target.value })

---

ポイント5：select の value も editForm に紐づける

志望度の例：

<select
value={editForm.priority}
onChange={(e) =>
setEditForm({ ...editForm, priority: e.target.value })
}

>

  <option value="1.0">1.0 なんとなく（練習用）</option>
  <option value="1.5">1.5 低め</option>
  <option value="2.0">2.0 少し気になる</option>
  <option value="2.5">2.5 検討中</option>
  <option value="3.0">3.0 普通</option>
  <option value="3.5">3.5 やや高め</option>
  <option value="4.0">4.0 かなり興味あり</option>
  <option value="4.5">4.5 本命</option>
  <option value="5.0">5.0 大本命</option>
</select>

理由：
志望度は自由入力にすると表記ゆれが起きやすい。
select にすることで、1.0〜5.0の0.5刻みに統一できる。

---

ポイント6：選考結果は status ではなく個別カラムで管理する

選考結果エリアでは、以下の値を使う。

書類選考：
editForm.document_result

1次面接：
editForm.first_interview_result

2次面接：
editForm.second_interview_result

最終結果：
editForm.final_result

落選段階：
editForm.rejection_stage

理由：
status に「書類通過」「1次面接落ち」「2次面接日程調整中」などを全部詰め込むと、選択肢が増えすぎてUXが悪くなる。
そのため、status は大きな状態、選考結果は各選考段階の結果として分けて管理する。

---

ポイント7：選考結果selectの選択肢

選考結果のselectでは、以下の選択肢を使う。

未対応
通過
不通過
保留
辞退

実装例：
<select
value={editForm.document_result}
onChange={(e) =>
setEditForm({ ...editForm, document_result: e.target.value })
}

>

  <option value="未対応">未対応</option>
  <option value="通過">通過</option>
  <option value="不通過">不通過</option>
  <option value="保留">保留</option>
  <option value="辞退">辞退</option>
</select>

---

落選段階は、どの段階で落ちたかを記録するための項目。

ポイント9：URLは input とリンク表示をセットにすると使いやすい

求人URLの例：

<input
value={editForm.job_url}
onChange={(e) =>
setEditForm({ ...editForm, job_url: e.target.value })
}
/>

{editForm.job_url ? (
<a
href={editForm.job_url}
target="\_blank"
rel="noreferrer"

>

    求人ページを開く

  </a>
) : (
  <p>未設定</p>
)}

理由：
URLは入力欄に入っているだけだと、実際に開きにくい。
リンク表示も用意すると、求人票や面談URLをすぐ確認できる。

---

ポイント10：保存ボタンは置くが、この時点ではPUTしない

セクション3では、保存ボタンを配置してもよい。
ただし、実際のPUT更新処理はセクション4で実装する。

実装例：
<button
type="button"
onClick={() => console.log("セクション4でPUT更新を実装")}

> 保存する
> </button>

理由：
セクション3のゴールは、現在データをモーダルフォームに表示すること。
保存処理まで入れると、状態管理・API更新・バリデーションが混ざって理解しにくくなる。

---

ポイント11：JSXを一気に理解しようとしない

このモーダルJSXは見た目のコード量が多い。
ただし、やっていることは大きく分けると以下だけ。

1. isModalOpen && selectedCompany で表示条件を決める
2. editForm の値を value に入れる
3. onChange で editForm を更新する
4. select で選択肢を固定する
5. 閉じるボタンで handleCloseModal を呼ぶ
6. 保存処理はまだ実装しない

この6点が分かれば、セクション3としては十分。

---

ポイント12：このセクションでまだやらないこと

PUT更新はしない。
UpdateCompanyRequestは作らない。
Laravelのupdateメソッドは作らない。
保存成功後の一覧再取得はしない。
バリデーションエラー表示はしない。
コンポーネント分割はまだ必須ではない。

このセクションでは、詳細ボタンから現在データ入りのモーダルを開けることに集中する。
