# セクション7の目的

## セクション名

CompanyTable分割・実用UI化

## 目的

検索・絞り込みまで終わった企業一覧を、`CompanyTable` コンポーネントに切り出し、実用的な一覧UIにする。

このセクションでは、単にテーブルを見やすくするだけではない。

以下を学ぶ。

- `App.tsx` から一覧表示を切り出す
- `CompanyTable` コンポーネントを作成する
- 親から子へ `companies` を props で渡す
- `loading` や空データ表示を扱う
- 詳細・削除ボタンを親の関数に接続する
- selectで志望度・状況を変更できるようにする
- 子コンポーネントから親の更新処理を呼ぶ
- favoriteボタンを追加する
- ハートSVGでお気に入り状態を表現する
- `isFavorite` や `status` に応じて行の見た目を変える
- 最初は5件だけ表示し、「もっと見る」で展開する

# セクション7の基本方針

## App.tsx と CompanyTable の責務

このセクションで最も重要なのは、親子コンポーネントの責務分離。

    App.tsx
    - companies stateを持つ
    - API通信を担当する
    - 登録・更新・削除・favorite切り替え処理を持つ
    - CompanyTableにデータと関数を渡す

    CompanyTable.tsx
    - companiesを表示する
    - loading中の表示を出す
    - 0件表示を出す
    - 詳細ボタンを表示する
    - 削除ボタンを表示する
    - 志望度selectを表示する
    - 状況selectを表示する
    - favoriteボタンを表示する
    - ボタンやselect操作があったら、propsで受け取った関数を呼ぶ

## 重要な考え方

    CompanyTableはAPI通信を担当しない。
    CompanyTableは、親から受け取ったデータを表示する。
    CompanyTableは、親から受け取った関数をイベント時に呼び出す。
    実際のDB更新や削除は、親App.tsx側の関数が担当する。

## レクチャー5：loading中・0件時の表示を追加する

### 対応する元項目

    6. loading表示を追加する
    7. 0件表示を追加する

### ゴール

API取得中とデータ0件時の表示を追加する。

### 扱う内容

- `loading: boolean` を props に追加する
- loading中は「読み込み中...」を表示する
- `companies.length === 0` の時は「企業データがありません。」を表示する
- 通常時だけ一覧を表示する

### 重要ポイント

loading表示と0件表示は別。

    loading中
    → まだAPI取得中

    0件表示
    → API取得は終わったが、データがない

この2つを分けることで、ユーザーに状態が伝わる。

### 想定時間

5分以内

## レクチャー6：詳細・削除ボタンを親の関数に接続する

### 対応する元項目

    8. 詳細ボタンを接続する
    9. 削除ボタンを接続する

### ゴール

`CompanyTable` 内のボタンから、親の詳細表示・削除処理を呼べるようにする。

### 扱う内容

- `onOpenDetail: (company: Company) => void` を props に追加する
- `onDelete: (id: number) => void` を props に追加する
- 詳細ボタンで `onOpenDetail(company)` を呼ぶ
- 削除ボタンで `onDelete(company.id)` を呼ぶ

### 重要ポイント

`CompanyTable` は詳細モーダルを自分で開かない。

`CompanyTable` は削除APIを自分で叩かない。

押された企業情報を親へ渡すだけ。

### 注意点

以下はダメ。

    onClick={onOpenDetail(company)}

これは描画時に即実行される。

正しくは以下。

    onClick={() => onOpenDetail(company)}

クリックされた時だけ実行するために、アロー関数で包む。

5分以内

## レクチャー8：志望度変更を親に通知する

### 対応する元項目

    12. 志望度変更を親に通知する

### ゴール

志望度 select の変更を親コンポーネントに通知する。

### 扱う内容

- `onPriorityChange: (company: Company, priority: string) => void` を props に追加する
- select の `onChange` で新しい値を取得する
- `onPriorityChange(company, event.target.value)` を呼ぶ

### 重要ポイント

新しい priority だけでは、どの企業の志望度を変えるのか分からない。

そのため、対象の `company` と、新しい値である `priority` の両方を渡す。

    onChange={(event) =>
      onPriorityChange(company, event.target.value)
    }

## レクチャー14：CompanyTable全体の責務を振り返る

### 対応する元項目

    24. セクション7全体を振り返る

### ゴール

`CompanyTable` 全体の責務と、親子コンポーネントの関係を整理する。

### 扱う内容

- CompanyTableが担当すること
- App.tsxが担当すること
- propsでデータを渡す
- propsで関数を渡す
- 子から親へ操作対象を渡す
- select変更とDB更新の関係
- favoriteと落選UIの意味
- もっと見るの仕組み

### 重要ポイント

このセクションの最終理解は以下。

    CompanyTableは一覧表示を担当する。
    App.tsxはstate管理とAPI通信を担当する。
    子コンポーネントはpropsでcompaniesを受け取る。
    子コンポーネントはpropsで関数を受け取り、クリックや変更イベントで親に通知する。
    どの企業を操作するか分かるように、companyやidを親へ渡す。
    select変更だけではDBは更新されない。
    親側の関数でAPI通信して初めてDBが更新される。
    favoriteはCompanyのis_favoriteを更新し、UIに反映する。
    落選企業は削除せず、学習ログとして残しつつ視覚的に弱める。
    もっと見るはDB再取得ではなく、フロント側の表示件数切り替え。

### 想定時間

5分以内
