# 1章：companies CRUD APIを作る

## 目的

Laravel側に companies CRUD API を作る。

この章では、CompanyResourceやFormRequestはまだ使わず、Controller内で `$request->validate()` と `$validated` を使って、まずCRUDの流れを理解する。

---

## この章でやること

```txt
1. CompanyController の index を確認
2. store を実装
3. update を実装
4. destroy を実装
5. Postman / Thunder Client / curl で動作確認
6. Reactで最低限の企業一覧を表示
```

---

## 1章のゴール

```txt
Laravel APIで企業データの一覧取得・登録・更新・削除ができる。

さらに、Reactから /api/companies をfetchして、
最低限の企業一覧を画面表示できる。
```

---

## 1章の方針

```txt
まずCRUDを動かすことを優先する。

きれいな設計は後回し。
CompanyResourceはまだ作らない。
FormRequestもまだ作らない。
Tailwindも深追いしない。
```

---

## Laravel側で作る処理

```txt
GET     /api/companies            index    一覧取得
POST    /api/companies            store    新規登録
PUT     /api/companies/{company}  update   更新
PATCH   /api/companies/{company}  update   一部更新
DELETE  /api/companies/{company}  destroy  削除
```

---

## Controller内の基本方針

```php
$validated = $request->validate([
    'name' => ['required', 'string', 'max:255'],
    'media' => ['nullable', 'string', 'max:255'],
    'priority' => ['nullable', 'string', 'max:255'],
    'status' => ['nullable', 'string', 'max:255'],
    'applied_date' => ['nullable', 'date'],
    'memo' => ['nullable', 'string'],
]);
```

---

## $validated の意味

```txt
$validated は、バリデーションを通過した安全な入力データ。

Reactから送られてきたデータをそのまま保存せず、
Laravel側でチェックしてからDBに保存する。
```
